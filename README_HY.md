# ProfRates — երկրորդ ուսանողի բաժին

Այս նախագիծը շարունակում է Step1-ը և երկրորդ բաժնի նախորդ փաթեթը՝ տարբերակ 0.3։ Իրականացվել է երկրորդ ուսանողի բաժինը՝ վերջնական HTML/CSS/JavaScript Frontend-ի և `script.sql`-ով հաստատված Microsoft SQL Server կառուցվածքի համար։ Բազայի ստեղծման, վերակառուցման կամ migration հրամաններ չկան։ Մյուս երկու ուսանողների նույնականացումն ու գնահատում ուղարկելու ծառայությունը չեն կրկնօրինակվել։

## 1. Տեղադրում Windows-ում

Անհրաժեշտ են Python 3.11+, գործող SQL Server բազան և Microsoft ODBC Driver 18 for SQL Server-ը։ Ապափաթեթավորեք նախագիծը, բացեք դրա պանակը VS Code-ում և գործարկեք՝

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

`requirements.txt`-ը թույլատրելի տարբերակների միջակայքն է, իսկ `requirements-tested.txt`-ը՝ այս միջավայրում թեստերի համար օգտագործված ճշգրիտ տարբերակները։

## 2. Միացնել առկա բազան

Տեղային `.env`-ում լրացրեք SSMS-ի Server name-ը և իրական բազայի անունը։ Արտահանված SQL-ի բազայի անունը `ProfRates_databaza` է. եթե ձեր համակարգչում այլ անունով է, գրեք այդ անունը։

```dotenv
DB_SERVER=localhost\SQLEXPRESS
DB_NAME=ProfRates_databaza
DB_TRUSTED_CONNECTION=true
DB_ENCRYPT=true
DB_TRUST_SERVER_CERTIFICATE=false
AUTH_PROVIDER=
AUDIT_PROVIDER=
```

Windows Authentication-ի դեպքում օգտագործվում է ընթացիկ Windows հաշիվը։ SQL Authentication-ի դեպքում դրեք `DB_TRUSTED_CONNECTION=false`, իսկ `DB_USER` և `DB_PASSWORD` լրացրեք միայն ձեր տեղային `.env`-ում։ Գաղտնաբառ մի ուղարկեք զրույցում և մի գրեք Python կոդում։ Հատուկ նիշերի դեպքում օգտագործեք dotenv-ի ճիշտ չակերտավորում։ `.env`-ը git-ից բացառված է։

Եթե տեղային SQL Server-ն ունի ինքնաստորագրված վկայական, հենց այդ տեղային միջավայրում անհրաժեշտության դեպքում `DB_TRUST_SERVER_CERTIFICATE=true` դրեք։ Գործող բազան մի ջնջեք և արտահանված `script.sql`-ը մի execute արեք։

```powershell
.venv\Scripts\python.exe -m tools.check_db
.venv\Scripts\python.exe -m tools.verify_schema
```

Առաջինը կատարում է `SELECT 1`, երկրորդը ստուգում է սպասվող աղյուսակների/view-երի դաշտերը և հայտնում տեսանելի ակտիվ trigger-ների անունները։ Եթե ձեր բազայում կան այս արտահանման մեջ չերևացող trigger-ներ, դրանց սահմանումները պետք է առանձին ուսումնասիրել՝ մասնավորապես audit-ի կրկնությունը բացառելու համար։

## 3. Գործարկել

```powershell

```

Հասցեներ՝

| Միացման ստուգում | http://127.0.0.1:8000/frontend/backend_check.html |
| Դասախոսների կառավարում | http://127.0.0.1:8000/frontend/admin_portal/professors_arm.html |
| Ուսումնական տվյալներ և կապեր | http://127.0.0.1:8000/frontend/admin_portal/academic_arm.html |

## 4. Ինչու ադմինի էջը կարող է վերադարձնել 401

Նույնականացումը առաջին ուսանողի բաժինն է։ Մինչ դրա միացումը՝ ադմինի API-ները դիտմամբ անհասանելի են։ Բաց ադմին գաղտնաբառ, փորձնական token կամ գաղտնի bypass չկա։ HTML էջի բացվելը տվյալներին հասանելիություն չի տալիս։

Առաջին ուսանողը պետք է տրամադրի server-side adapter՝ `module:function` ձևաչափով, որը ստուգում է session/JWT-ն և վերադարձնում մեր `Principal`-ը։ `.env`-ում նշվում է adapter-ի անունը, օրինակ `AUTH_PROVIDER=team_auth.adapter:resolve_principal`։ Կոդի պայմանագիրը՝ `docs/INTEGRATION_HY.md`։ Պետք է տրամադրվի իրական `Admins.AdminID`, ոչ ուսանողի `Users.UserID`։ Սխալ կամ բացակայող AdminID-ի դեպքում API-ն մերժում է գործողությունը։

Միացնելուց հետո կարելի է ադմինի UI-ով ամբողջությամբ կառավարել երկրորդ բաժնի տվյալները։ Մինչ այդ հանրային ընթերցումն աշխատելու համար նույնականացում անհրաժեշտ չէ։

## 5. Գործնական ստուգում՝ նույնականացումը միացնելուց հետո

1. Դասախոսների էջում սեղմեք «Ավելացնել դասախոս», լրացրեք անունը և անհրաժեշտ դաշտերը։ Պահպանեք, թարմացրեք էջը. գրառումը պետք է մնա։
2. Փոխեք անունը, փորձեք որոնումը և կարգավիճակի/ամբիոնի ֆիլտրերը։ Անունն ու ազգանունը առանձին դաշտեր են։
3. Ապաակտիվացրեք դասախոսին. ադմինի ցուցակում նա կլինի պասիվ, հանրային էջից կվերանա, նախկին գնահատումները չեն ջնջվի։
4. Ուսումնական տվյալների էջում ընտրեք բաժինը՝ ինստիտուտ, ֆակուլտետ, ամբիոն, մասնագիտացում, խումբ կամ առարկա։ Ամբիոնն ունի միայն մեկ ծնող՝ ինստիտուտ ԿԱՄ ֆակուլտետ։
5. Առարկայի ձևում ընտրեք դասախոսին. սա իրական դասախոս–առարկա կապն է։ Եթե առարկան արդեն գնահատումներ ունի, դասախոսի փոխարինումն արգելվում է՝ պատմությունը չխախտելու համար։ Ստեղծեք նոր առարկայի գրառում։
6. Նույն էջի «Ուսանող–առարկա կապեր» բաժնում ընտրեք ուսանողին և առարկան։ Կրկնվող կապը մերժվում է։ Կապը հեռացնելը նախկին գնահատումները չի ջնջում։
7. Հարցաշարում ավելացրեք հարց։ Այն հայտնվում է նաև գնահատման էջում։ ↑/↓ կոճակները փոխում են ակտիվ հարցերի ընդհանուր հերթականությունը։
8. Եթե արդեն պատասխանված հարցի տեքստը կամ բաժինը փոխեք, ստեղծվում է նոր ID-ով հարց, իսկ հինը ապաակտիվացվում է։ Հին պատասխանները պահպանում են իրենց սկզբնական հարցը։
9. Մեկնաբանությունների էջում հաստատեք կամ մերժեք գրառումը։ Կարգավիճակն ազդում է ամբողջ գնահատման վրա. բազայում առանձին մեկնաբանության կարգավիճակ չկա։ Հանրային էջում երևում են միայն հաստատվածները՝ առանց ուսանողի տվյալների։
10. Արտահանման կոճակները ներբեռնում են UTF-8 CSV։ Դասախոսների, ուսումնական տվյալների և մեկնաբանությունների export-ը ընթացիկ էջն է՝ մինչև 100 գրառում API-ով։ Հարցաշարի export-ը ամբողջ ցանկն է։ CSV-ում բանաձևի նմանվող տեքստերը պաշտպանված են։

## 6. Ինչ է միացված Frontend-ում

Հայերեն գլխավոր էջեր՝ իրական դասախոսների ցանկ, որոնում, ամբիոնի ֆիլտր, դասավորում և էջավորում։ Հայերեն և անգլերեն դասախոսի էջեր՝ իրական տվյալներ, հաստատված անանուն մեկնաբանություններ և «Բեռնել ավելին»/Load more էջավորում։ Բաշխման դիագրամի կեղծ տոկոսները հանված են. վիճակագրական բաշխումը երրորդ բաժնի միացման խնդիրն է։

Հայերեն ադմինի դասախոսների, հարցերի, մոդերացիայի էջերն ու նոր ուսումնական տվյալների էջը API են կանչում։ Գործողությունն ավարտված է համարվում միայն բազայի transaction-ի հաջող ավարտից հետո։ CSS ֆայլերը չեն փոփոխվել. պահպանվել են պատրաստ էջերի հիմնական կառուցվածքն ու դասերը, ավելացվել են անհրաժեշտ դաշտեր և կառավարիչներ։

Հարցաշարի 12/10 տարբերությունը վերացված է ցուցադրման աղբյուրի մակարդակում. երկու էջերն էլ բեռնում են բազայի հարցերը։ `script.sql`-ում 6 ակտիվ հարց է արտահանված. իրական քանակը որոշվում է գործող բազայի տվյալներով։ Backend-ը ինքնուրույն հարցեր չի ավելացնում կամ ջնջում։

Երկրորդ բաժնի անգլերեն էջերը նույնպես միացված են նույն API-ներին՝ անգլերեն կոճակներով, ձևերով և հաղորդագրություններով։ `student2_i18n.js`-ը թարգմանում է միջերեսը, ոչ բազայի անուններն ու հարցերի բովանդակությունը։ Հայերենը մնում է լռելյայն։ Առաջին ուսանողի login/user-management և երրորդի ranking/ratings էջերի կոդը չի փոխարինվել։

## 7. Թեստեր և սահմանները

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

Այս միջավայրում թեստերն օգտագործում են առանձին SQLite հիշողության բազա և SQL Server-ի տրամաբանությունը ներկայացնող թեստային view-եր։ Դրանք չեն ստուգում SQL Server-ի իրական driver-ը, collation-ը, constraint-ների ամբողջությունը, trigger-ները, locking-ը կամ ցանցային միացումը։ SQL Server-ի համար հարցման գեներացման ստուգում նույնպես կա, բայց դա իրական կատարում չէ։ Production կոդում SQLite fallback չկա։

Իրական բազայով ստուգելու համար կատարեք 2-րդ և 5-րդ քայլերը։ Այս միջավայրից ձեր SQL Server-ին մուտք չի եղել. իրական բազայի հետ CRUD-ի հաջողություն չի պնդվում։ Մանրամասն արդյունքները՝ `docs/TEST_REPORT_HY.md`։ Տեղային MSSQL փորձարկման ամբողջ ընթացքը՝ `docs/LOCAL_MSSQL_CHECKS_HY.md`, նույնականացման կոնկրետ միացումը՝ `docs/AUTH_CONNECTION_HY.md`։

## Կոդի հիմնական ֆայլերը

- `app/student2/tables.py` և `docs/verified_schema.json`՝ իրական schema-ի mapping, առանց բազայի ստեղծման։
- `schemas.py`՝ մուտքային դաշտերի ստուգում։
- `service.py`՝ պահպանման կանոններ, պատմության պաշտպանություն և audit-ի միացման կետ։
- `router.py`՝ հանրային և ադմին API-ներ։
- `dependencies.py`՝ transaction, SQL սխալների անվտանգ պատասխաններ և իրական AdminID-ի ստուգում։
- `app/security.py`՝ առաջին բաժնի նույնականացման adapter։
- `frontend/.../student2_*.js`՝ կոճակների և API-ի կապ։
- `docs/DEFENSE_HY.md`՝ պաշտպանության համար կարճ բացատրություն։


## 0.3 տարբերակի նպատակային լրացումները

Ուսանող–առարկա կապերի `q` որոնումն այժմ աշխատում է անունով, ազգանունով, խմբով և առարկայով, նաև արտահանման ժամանակ։ Որոնման բառերը համակցվում են AND-ով, տարբեր դաշտերի համընկնումները՝ OR-ով։ `%` և `_` նիշերը որոնվում են որպես տեքստ, ոչ wildcard։

Անգլերեն միացված էջերը՝ `admin_portal/professors.html`, `admin_portal/RatingQuestions.html`, `admin_portal/ratings&reviews.html`, նոր `admin_portal/academic.html`, `home_eng*.html`, `prof_eng*.html`, `rate_eng.html`։ Առկա CSS-ը չի փոփոխվել։ Հարցերի բազային տեքստը պահպանվում է իր սկզբնական լեզվով։

Հանրային մեկնաբանությունները բեռնվում են 20-ական։ Հաջորդ էջի ձախողման դեպքում հնարավոր է կրկին փորձել՝ առանց արդեն ցուցադրված գրառումները կրկնելու։

`tools.verify_schema`-ը ստուգում է դաշտերի տեսակները, երկարությունները, NULL-ը, IDENTITY-ն, PK/FK/UNIQUE բանալիները։ Այն չի հաստատում backup-ի schema-ն կամ trigger-ների ամբողջական վարքը։ Կառուցվածքային համընկնումը և իրական runtime ստուգումը տարբեր արդյունքներ են։

`tools.smoke_mssql`-ը լռելյայն միայն ընթերցում է։ Միայն `--write-rollback --admin-id N`-ով այն փորձում է նոր fixture-ների գրառումները մեկ transaction-ում և վերջում հետ է գլորում։ Սա նույնականացման կամ commit-ից հետո էջի պահպանման թեստ չէ։ Առկա բազան չի վերաստեղծվում։
