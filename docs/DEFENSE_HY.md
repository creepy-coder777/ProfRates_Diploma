# Պաշտպանության համար կարճ բացատրություն

Ես իրականացրել եմ համակարգի երկրորդ մասնակցի բաժինը՝ դասախոսների և ուսումնական տվյալների կառավարում, հարցաշար և մեկնաբանությունների մոդերացիա։ Python/FastAPI-ն ընդունում է Frontend-ի հարցումները, ստուգում մուտքային տվյալներն ու իրավունքները և SQLAlchemy/pyodbc-ի միջոցով աշխատում առկա SQL Server բազայի հետ։ Բազան չի վերաստեղծվում։

Էջի կոճակը կանչում է API-ն։ API-ն ստուգում է՝ օգտատերը իրական ադմին է, դաշտերը ճիշտ են, և կապվող գրառումները գոյություն ունեն։ Փոփոխությունը և գործողության մատյանը կատարվում են մեկ transaction-ում։ Միայն հաջող commit-ից հետո Frontend-ը ստանում է հաջող պատասխան և նորից բեռնում ցուցակը։ Այդ պատճառով տվյալները պահպանվում են նաև էջը թարմացնելուց հետո։

Դասախոսների և ուսումնական գրառումների ջնջման փոխարեն օգտագործվում է IsActive դաշտը։ Նախկին գնահատումներն ու կապերի պատմությունը ֆիզիկական ջնջմամբ չեն կորում։ Առարկայի դասախոսը հնարավոր չէ փոխել, եթե այն արդեն գնահատումներ ունի. այդ դեպքում անհրաժեշտ է առանձին առարկայի գրառում։

Հարցաշարի երկու էջերն օգտագործում են բազայի նույն ակտիվ հարցերը։ Եթե արդեն պատասխանված հարցի իմաստը փոխվում է, հինը ապաակտիվացվում է և ստեղծվում նոր ID-ով հարց։ Նախկին RatingAnswers գրառումները պահպանում են իրենց սկզբնական QuestionID-ն։

Մեկնաբանության հաստատումը փոխում է առկա Ratings.Status-ը։ Քանի որ բազայում կարգավիճակը ամբողջ գնահատմանն է վերաբերում, դրա հետ փոխվում է նաև վարկանիշում ընդգրկվելը։ Հաշվարկը նորից չեմ գրել Python-ում. առկա SQL view-ն ինքն է հաշվի առնում միայն Approved գրառումները։ Հանրային view-ից վերցվում են միայն թույլատրելի դաշտերը՝ առանց ուսանողի անունի, էլփոստի կամ ID-ի։

Առաջին ուսանողը տրամադրում է նույնականացումն ու ստուգված AdminID-ն, երրորդը՝ գնահատումների պահպանումը, գնահատելու իրավունքը, հավանումներն ու հաշվարկների մնացած մասը։ Առանց նրանց միացման փորձնական բաց ադմին մուտք կամ գնահատման կեղծ հաջողություն չկա։

Թեստերը ստուգում են API-ի կանոնները, պահպանումը թեստային բազայում, պատմության պահպանումը, իրավունքները և մոդերացիան։ Իրական SQL Server-ի հետ վերջնական ինտեգրումը պետք է ստուգել տեղային համակարգչում. թեստային բազայի հաջողությունը չեմ ներկայացնում որպես իրական SQL Server-ով ստուգում։
