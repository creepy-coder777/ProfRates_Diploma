## Նոր նպատակային ստուգումներ

Ուսանող–առարկա որոնումը ստուգվել է անունով, ազգանունով, երկու բառով, խմբի կոդով և առարկայի անվանումով։ Ստուգվել են նաև q-ի համակցումը user_id/course_id ֆիլտրերի հետ, նույն արտահանման ֆիլտրերը, չգտնված արժեքները, չափազանց երկար մուտքը, SQL injection-ի նման տեքստը և `%`/`_`-ի տեքստային որոնումը։

Մեկնաբանությունների API-ի 23 գրառումները բաժանվել են 20 և 3 գրառումներով էջերի՝ առանց ID-ների կրկնման։ DOM ստուգմամբ Load more կոճակը բեռնել է 20-ից հետո մնացած 3-ը և թաքնվել։ Հաջորդ էջի միտումնավոր ձախողումից հետո Try again-ը հաջողությամբ կրկնել է բեռնումը՝ առանց արդեն ցուցադրված մեկնաբանությունների կրկնության։

Անգլերեն դասախոսների էջում փորձարկվել են ցուցակն ու խմբագրման անգլերեն ձևը։ Ստուգվել են անգլերեն հարցաշարի հաղորդագրությունները, մոդերացիայի կոճակները, ուսումնական տվյալների ընտրիչը և ուսանող–առարկա որոնումը։ Երկու լեզուներն օգտագործում են նույն API-ները։ Բազայի հայերեն տվյալները չեն թարգմանվում։

Schema verifier-ի թեստերը ներառում են ճիշտ contract, սխալ SQL տեսակ, nvarchar-ի սխալ byte length, սխալ NULL/IDENTITY, բացակայող PK/UNIQUE, չվստահված FK, composite key-ի սխալ հերթականություն, լրացուցիչ պարտադիր դաշտ, metadata-ի անբավարար իրավունք, view-ի տեքստային տարբերություն և անհայտ trigger-ի բացահայտ նշում։

MSSQL rollback փորձարկման սցենարը կատարվել է միայն SQLite fixture-ի վրա՝ հաստատելով, որ նոր տվյալները հետ են գլորվում, իսկ նախկին աղյուսակների գրառումների քանակը չի փոխվում։ Սա SQL Server locking/trigger/IDENTITY վարքի ապացույց չէ։

Նույնականացման bridge-ը ստուգվել է՝ այն մերժում է client header-ները, չստուգված state-ը և սխալ դերային տեսակը։ check_auth գործիքի թեստերը mock HTTP արդյունքներով են և իրական առաջին բաժնի ինտեգրում չեն նշանակում։ Credential-ները հաշվետվություններում չեն պահպանվում։

## Նախորդ հիմնական թեստերը նույնպես անցել են

Դասախոսների և ուսումնական օբյեկտների CRUD/ապաակտիվացում, պահպանում թեստային բազայում, կապերի կրկնության մերժում, հարցերի պատմություն և հերթականություն, հաստատում/մերժում, հանրային անանունություն, բոլոր ադմին գործողությունների իրավունքներ, transaction-ի հետգլորում, audit-ի մեկանգամյա կանչ, պարամետրավորում և CSV պաշտպանություն։

## Ինչպես ստանալ իրական MSSQL ապացույցը

`LOCAL_MSSQL_CHECKS_HY.md`-ի հրամանները ստեղծում են schema_verification և mssql_smoke_report հաշվետվությունները։ Միայն ձեր համակարգչում այդ գործիքների իրական հաջող կատարումից հետո կարելի է համապատասխան գործողությունները նշել որպես MSSQL-ով ստուգված։ ROLLBACK սցենարի հաջողությունն էլ չի հաստատում առաջին բաժնի auth-ը կամ commit-ից հետո էջի պահպանումը. դրանց համար կան առանձին իրական login/UI քայլեր։

Pytest-ը տվել է մեկ Starlette/httpx deprecation զգուշացում. թեստերի արդյունքը հաջող է։
