# Demo-ի ուսումնասիրություն — 24.10.2026

Հիմք՝ հենց ProfRates_Demo.zip-ի կոդը։ Նախկին Student2 փաթեթի փոխարեն ուսումնասիրվել է այս նոր տարբերակը, որն արդեն ներառում է auth և Student3 բաժինները։ SQL migration-ները չեն կատարվել։ .env-ը կարդացվել է միայն կարգավորումների վերլուծության համար, գաղտնի արժեքները չեն հրապարակվել։

## Այստեղ ուղղվածը

1. Remember me-ն արդեն ուղարկվում է մուտքի API-ին։ Չնշվածի դեպքում ուսանողի cookie-ն browser session cookie է՝ server-side SESSION_HOURS ժամկետով։ Նշվածի դեպքում cookie-ն և server session-ը ունեն նույն REMEMBER_SESSION_DAYS օր ժամկետը՝ լռելյայն 14, թույլատրելի՝ 1–30։ Logout-ը և password reset-ը շարունակում են չեղարկել session-ները։ Նոր SQL դաշտ չի պահանջվում։ Browser-ի session restore գործառույթը կարող է վերականգնել նաև session cookie, ուստի «չնշել»-ը բացարձակ երաշխիք չէ, որ browser-ի փակվելը server session-ը անմիջապես կչեղարկի։
2. Հանրային դասախոսի էջում արդեն գրանցված ուսանողի նախորդ like/dislike ընտրությունը կարդացվում է նաև guest անունով էջում։ Նախկինում դա որոշվում էր URL-ի անունով, իսկ հիմա՝ սերվերի իրական session-ով։ Կոճակները սկզբնական վիճակի բեռնման ընթացքում ժամանակավորապես անջատված են։ Trigger-ի հաշվարկը չի կրկնվել Python-ում։
3. Վիճակագրության distribution_unit-ը դարձել է question_answers։ Ներկա SQL migration-ն ու թեստերը ներառում են նաև Pending/Rejected գնահատումների միավորները, ուստի approved_question_answers նախկին պիտակը սխալ էր։ Հաշվարկի քաղաքականությունը չի փոխվել։

Փոփոխված հիմնական ֆայլերը՝ app/config.py, app/auth/schemas.py, app/auth/service.py, app/auth/router.py, app/student3/service.py, frontend/js_codes/ui_auth_forms.js, frontend/js_codes/student2_profile.js, .env.example, tests/test_accounts.py։

## Ինչն է արդեն լավ իրականացված

Կան գաղտնաբառերի հեշավորում, server-side session, CSRF ստուգում, ադմին/ուսանող բաժանում, email/reset մեկանգամյա հղումներ, տեղային մասնավոր փոստարկղ, գնահատումների սեփականատիրոջ ստուգում, հարցերի պատմություն, API-ներով պահպանվող տվյալներ և ռեգրեսիոն թեստեր։ Դրանք գործնական իրականացումներ են, ոչ միայն ցուցադրական կոճակներ։

Սկզբնական Demo-ի 104 թեստերն այստեղ անցել են։ Remember me-ի նոր վարքի երկու թեստով ուղղված տարբերակում անցել է 106 թեստ։ Դրանք SQLite/մակետային dependency-ներով թեստեր են, ոչ իրական MSSQL ինտեգրացիոն ապացույց։ Փոփոխված JavaScript-ը ստուգված է շարահյուսական մակարդակով։ Այս վերանայման ընթացքում browser-ում Remember me/like փոխազդեցությունը չի գործարկվել։

## Ինչը պետք է ավարտել SQL-ից բացի

### 1. Թարգմանության պահանջը դեռ լիովին կատարված չէ

Frontend-ում կան առանձին հայերեն/անգլերեն HTML էջեր, `text(hy, english)` և JS թարգմանությունների բառարաններ։ Backend-ի localization.py-ն տալիս է անունների տառադարձում և որոշ ամբիոնների բառարանային թարգմանություն։ Սա ամբողջ միջերեսը մեկ հայերեն աղբյուրից Backend-ի թարգմանության ծառայությամբ ստանալու ամբողջական լուծում չէ։

Հաջորդ առանձին փոփոխությունը պետք է լինի ընդհանուր էջային աղբյուր, server-side message catalog/թարգմանության ծառայություն, լեզվի փոխարկում և cache/fallback։ Մինչ մատակարար/տեխնոլոգիա ընտրելը ոչ մի արտաքին ծառայության չեն ուղարկվել անձնական տվյալներ կամ մեկնաբանություններ։ Gettext/Babel տեսակի message catalog-ը և մեքենայական թարգմանությունը տարբեր խնդիրներ են. առաջինը հարմար է UI-ին, երկրորդը կարող է անհրաժեշտ լինել փոփոխվող տեքստերի համար։ Մատակարարն այստեղ չի ընտրվել կամ միացվել։

### 2. Նոր ուսանողի գրանցումը դեռ ինքնուրույն գնահատելու իրավունք չի ստեղծում

Գրանցումը պահում է GroupID-ն։ Գնահատման թույլտվությունը լրացուցիչ պահանջում է StudentCourses և StudentAcademicProgress գրառումներ։ Պետք է կազմակերպել դրանց լրացման հաստատված ուսումնական գործընթացը՝ ադմինով կամ համաձայնեցված ներմուծմամբ։ Դատարկ rating-options-ը պարտադիր Frontend-ի սխալ չէ։ Խմբին կամ կիսամյակին ենթադրաբար կապեր չենք ավելացրել։

### 3. Ընթացիկ կիսամյակի կանոնը պետք է ստուգել

Student3 eligibility_query-ը հենվում է IsCurrent=1-ի և ուսումնական կիսամյակի համապատասխանության վրա։ Այն չի սահմանափակում StartsOn/EndsOn ամսաթվերով։ Եթե ձեր ընթացիկության պաշտոնական կանոնը ամսաթվերով SQL view-ն է, այդ երկու մեխանիզմները պետք է համաձայնեցնել։ Մինչ այդ հին IsCurrent գրառումը կարող է թողնել գնահատելու իրավունքը։ Այստեղ կանոնը ինքնակամ չի փոխվել։

### 4. Իրական account/email ամբողջական փորձարկում

MAIL_BACKEND=local-ը իրական email չի ուղարկում։ Գրանցում → local mailbox-ի verification link → մուտք → logout → reset → նոր գաղտնաբառով մուտք շղթան պետք է կատարել տեղային browser-ում։ Production-ի համար պետք է իրական mail provider և HTTPS/cookie կարգավորում։ Demo-ն production readiness չի հաստատում։

### 5. Like/dislike և մոդերացիա՝ իրական session-ով

Պետք են RatingReactions աղյուսակն ու tr_RatingReactions_Counters միացված trigger-ը։ Ստուգել՝ like → կրկին like (հեռացում) → dislike → հեռացում → էջի թարմացում, նաև guest URL-ում մուտք գործած օգտատիրոջ վիճակ։ Browser Network-ում սխալի status-ը կարևոր է՝ 401 մուտք, 403 CSRF/իրավունք, 503 DB կամ բացակայող օբյեկտ։ Առանց իրական MSSQL արձագանքի չի կարելի ասել, թե որ պատճառը կա ձեր մոտ։

### 6. Կոդի և փաստաթղթերի միատեսակեցում

Կան հին Student2 շրջանի ուղեցույցներ՝ auth-ը բացակայող ներկայացնող տեքստերով և հաստատված գնահատումներից հաշվարկ նկարագրող հին կանոններով։ Ներկա կոդը արդեն ունի auth և բոլոր գնահատումների միավորների հաշվարկի SQL migration։ SQL-ի վերջնական քաղաքականությունը հաստատելուց հետո պետք է թարմացնել հիմնական README-ն, schema contract-ը, գործարկման հերթը և թեստերի հաշվետվությունը՝ մեկ վերջնական տարբերակի շուրջ։ Հին ու նոր SQL ֆայլերը հերթով կուրորեն գործարկել պետք չէ։

## Ինչպես ստուգել գործող բազան հիմա՝ առանց այն փոխելու

```powershell
.venv\Scripts\python.exe -m tools.check_db
.venv\Scripts\python.exe -m tools.check_auth_schema
.venv\Scripts\python.exe -m tools.check_student3
```

Սրանք միայն ընթերցման ստուգումներ են։ Հաջորդը իրական browser-ի գրանցում/login/admin/reactions քայլերն են։ Կառուցվածքային ստուգման READY պատասխանը trigger-ի կատարումը չի փորձարկում։ Բազայի ուղղումներից հետո ուղարկեք թարմ Schema only արտահանում՝ ներառյալ view/procedure/trigger սահմանումները։

## Փաթեթի մաքրում

Այս ուղղված ZIP-ից բացառվել են .env-ը, var/mailbox-ը, session/reset link-երի հնարավոր ֆայլերը, exports-ը, .venv-ը և __pycache__-ը։ Այն բացեք նոր պանակում և ձեր տեղային .env-ը պահեք միայն ձեր համակարգչում։ Եթե օգտվում եք գոյություն ունեցող .env-ից, REMEMBER_SESSION_DAYS-ը կարող է բացակայել՝ կիրառվում է անվտանգ սահմանված default-ը։ Լրացուցիչ SQL migration չենք ավելացրել և չենք գործարկել։ Սկզբնական Demo-ի կոդն ու SQL ֆայլերը մնում են առանձին սկզբնական ZIP-ում։
