# Ադմինի հաշիվներ և գնահատումների մոդերացիա — 2026-11-06

## Աշխատանքային տարբերակ

Փոփոխությունները կատարվել են `preview_latest/ProfRates_Student2` նախագծում՝ `feature/admin-students-moderation` ճյուղում։ Մեկնարկային commit-ը՝ `f1b8311`։ GitHub push չի կատարվել։ Իրական տվյալների բազայում DDL/DML չեմ կատարել։ `.env`-ը և տեղային նամակները չեն փոփոխվել և չեն ավելացվել Git-ում։

## Ինչ է փոխվել

1. Հանրային գրանցման երկու էջերը և դրանց հղումները հեռացված են։ `/api/auth/register` և `/api/auth/registration-groups` endpoint-ները հեռացված են։ Գրանցումը հնարավոր չէ նաև ուղիղ API կանչով։
2. Ադմինի «Օգտատերեր» բաժնում «Ավելացնել ուսանող» ձևը ստեղծում է իրական `Users` հաշիվ, ոչ գրանցման թույլտվություն։ Մուտքագրվում են անունը, ազգանունը, `@polytechnic.am` էլփոստը, խումբը, 12–128 նիշ գաղտնաբառը և դրա կրկնությունը։ Backend-ը ստուգում է դաշտերը, կրկնվող հասցեն և խմբի/մասնագիտության/ամբիոնի ակտիվությունը։
3. Նոր հաշիվը `Active` է և պատրաստ մուտքի համար։ Առկա `IsEmailVerified` դրոշը սահմանվում է true՝ լիազորված ադմինի կողմից հաստատված հաշվի պայմանավորվածությամբ։ Սա իրական փոստարկղի վերահսկողության տեխնիկական հաստատում կամ ուղարկված նամակ չի նշանակում։ Հին հաշիվները ինքնաշխատ չեն ակտիվացվում/հաստատվում։
4. Գաղտնաբառի համար օգտագործվում է գործող աղով PBKDF2 հեշավորումը։ Գաղտնաբառը չի վերադարձվում API-ում և չի գրանցվում audit-ում։ Դեկանատը պետք է փոխանցի այն անձնական անվտանգ եղանակով։ Գաղտնաբառի փոփոխման նոր գործառույթ չի ավելացվել․ գործող վերականգնումը պահպանված է։
5. Հաշիվը, ուսումնական կապերն ու audit-ը պահվում են մեկ գործարքում։ Առկա `sync_student` մեխանիզմը օգտագործում է ընթացիկ շրջանը, խմբի ընդունելության տարին և տվյալ մասնագիտության/կիսամյակի ակտիվ առարկաներն ու դասախոսները։ Բաց տվյալները չեն հորինվում։ Հաշիվը կարող է ստեղծվել `curriculum-missing` կամ այլ բացատրելի ակադեմիական զգուշացումով, բայց գնահատման իրավունք չի հորինվում։
6. Ուսանողների ցուցակում ավելացված են խումբը, մասնագիտությունը, կուրսը և ֆիլտրերը՝ ինստիտուտ, ֆակուլտետ, ամբիոն, մասնագիտություն, խումբ, կուրս, կարգավիճակ։ Կուրսը՝ ընթացիկ կիսամյակի 1–2 → 1, 3–4 → 2, 5–6 → 3, 7–8 → 4։ Եթե ընթացիկ առաջընթացը բացակայում է կամ երկիմաստ է, կուրսը ցուցադրվում է չսահմանված։ Խմբի անվան թվերից ենթադրություններ չեն արվում։ Ֆիլտրերը համատեղ կիրառվում են, ցանկերն անկախ են։
7. `StudentRoster`-ի runtime կախվածությունն ու դրա admin endpoint-ները հեռացված են։ Աղյուսակը ստեղծելու անհրաժեշտություն չկա։ Եթե հին բազայում այն կա, տվյալները չեն ջնջվում։ Միգրացիա 04-ը պահպանված է միայն պատմական համատեղելիության համար, նոր հոսքին անհրաժեշտ չէ։
8. Առանց մեկնաբանության կամ բառացանկի համընկնում չունեցող մեկնաբանությամբ գնահատումը `Approved` է։ Համընկնումով ամբողջ գնահատումը `Pending` է։ Ստուգումը կիրառվում է և ստեղծելիս, և փոփոխելիս։ Ադմինի մերժումը նշանակում է ամբողջ գնահատման `Rejected`։ Հին գնահատումների կարգավիճակները զանգվածաբար չեն փոխվել։
9. Բառերն ու արտահայտությունները խմբագրվում են `app/student3/moderation_terms.json`-ում։ Փոփոխությունից հետո վերագործարկել սերվերը։ Կիրառվում է Unicode NFKC, նույն տառաչափ, անտեսանելի format նիշերի հեռացում և ամբողջական բառերի/արտահայտությունների համընկնում։ «Վատ է բացատրում» նման քննադատությունը թույլատրվում է։ Սա իմաստային կամ AI մոդերացիա չէ․ քողարկված, տառադարձված և հոլովված վիրավորանքները կարող են չհայտնաբերվել, մեջբերումները՝ սխալ նշվել։ Խափանված բառացանկը չի անջատում զտումը լուռ։
10. Դասախոսների մի մասի համար ավելացված են երկու գեներացված ցուցադրական դիմանկարներ։ Տեղային display mapping-ը `app/localization.py`-ում է՝ Ռուզաննա/Տաթևիկ/Անի → կին, Վահե/Արամ/Սուրեն → տղամարդ։ Այլ անունները պահպանում են ավատարը։ Բազայի իրական PhotoUrl-ը չի վերագրվում։ Գլխավոր և անհատական էջերում նշվում է «Ցուցադրական դիմանկար»։
11. Դասախոսի «Առարկաներ» էջում ավելացված է վերադարձ դասախոսների ցանկին՝ պահպանելով էջը, որոնումն ու ֆիլտրերը։ Վերադարձի հասցեն սահմանափակված է նույն կայքի դասախոսների ցանկով՝ արտաքին redirect չստեղծելու համար։
12. Ադմինի վահանակի միջինը և հարցերի պատասխանների բաշխումը ներառում են միայն Approved գնահատումները։ Դասախոսների SQL ամփոփումների սահմանափակումը նկարագրված է ստորև։

## SQL-ի կարևոր սահմանափակումը

Իմ գործընթացից իրական SQL Server-ին միանալու փորձն ավարտվել է `OperationalError`-ով։ Ձեր գործարկած միացման հաջողությունը պահպանվում է որպես ձեր փորձարկման արդյունք, բայց իմ իրական բազայի ստուգում չէ։ Ամբողջական live schema/trigger/SP վարքը այս փուլում չի հաստատվել։

Նախագծի `02_upgrade_student3.sql`-ի հին սահմանումները հաշվում են նաև Pending/Rejected գնահատումները։ Ձեր բազայի իրական սահմանումները կարող են արդեն տարբերվել։ Նոր պահանջը հնարավոր չէ լիարժեք երաշխավորել, քանի դեռ դրանք չեն ստուգվել։

- `docs/REVIEW_RATING_POLICY.sql` — միայն կարդացող հարցում՝ գործող view-երի և վարկանիշի ընթացակարգի սահմանումները ստանալու համար։ Նախ գործարկեք սա SSMS-ում։
- `database/05_approved_rating_policy_REVIEW_ONLY.sql` — պատրաստված, **չկիրառված** թեկնածու ուղղում՝ միայն երկու ամփոփման view-երում Approved ֆիլտր ավելացնելու համար։ Աղյուսակներ, տվյալներ, trigger-ներ և բայեսյան գործակիցներ չի փոխում։ Չի գործարկվում startup-ի ժամանակ։ Գործող սահմանումներն ու պահուստային պատճենը ստուգելուց և համաձայնեցնելուց առաջ մի կիրառեք։ Այն նախատեսված է նախագծի հայտնի 02 սահմանումների համար, անհայտ այլ հաշվարկը վերագրելու համար չէ։
- Վարկանիշի բանաձևը Python-ում չի կրկնվել։ `/api/rankings`-ը շարունակում է օգտագործել `dbo.uspLecturerRankings`-ը։ Անհրաժեշտ է հաստատել, որ ընթացակարգը հենվում է ճիշտ ամփոփումների վրա։
- Մի գործարկեք 02-ը նորից միայն ստուգումն անցնելու նպատակով․ այն կարող է վերադարձնել հին վարքը։

## Գործարկում և ցուցադրում

1. VS Code-ում բացել նույն `ProfRates_Student2` պանակը։ Git Bash՝ `source .venv/Scripts/activate`։
2. `python -X utf8 -m tools.check_db` և `python -X utf8 -m tools.check_auth_schema`։ Այժմ StudentRoster-ի բացակայությունը չի արգելափակի գործարկումը։ Մյուս իրական բացակայությունները պետք է ուսումնասիրել։
3. Եթե սերվերն արդեն աշխատում է, Ctrl+C-ով դադարեցնել միայն դրա տերմինալում և նորից գործարկել՝ `python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000`։
4. Բացել `http://127.0.0.1:8000/frontend/admin_portal/Admin_login_arm.html`, մուտք գործել գործող ադմինի հաշվով։ Անհրաժեշտության դեպքում գործող տեղային `tools.admin_account recover` գործիքը պահպանված է։
5. «Օգտատերեր» → «Ավելացնել ուսանող»։ Ընտրել իրական ակտիվ խումբ, մուտքագրել դեկանատի որոշած թեստային հասցեն և գաղտնաբառը։ Ստուգել ստեղծման հաղորդագրությունն ու ակադեմիական զգուշացումը։
6. Ստուգել որոնումը և բոլոր ֆիլտրերը։ Անհայտ կուրսով հաշիվը չի հայտնվի որոշակի կուրսի ֆիլտրում, մինչև ակադեմիական տվյալները չլրացվեն։
7. Դուրս գալ ադմինից կամ բացել առանձին մասնավոր պատուհան, բացել `/frontend/login_arm.html` և մուտք գործել նոր ուսանողով՝ առանց հանրային գրանցման կամ հաստատման նամակի։
8. Եթե ընթացիկ ուսումնական կապեր կան, գնահատել դասախոսին սովորական մեկնաբանությամբ՝ օրինակ «Վատ է բացատրում»։ Ստանալ Approved։ Այլ թույլատրված առարկայի գնահատման մեջ գրել «ապուշ»՝ ստանալ Pending։ Նույն ուսանող–դասախոս–առարկա կրկնությունը շարունակում է մերժվել։
